# 标准制作角色资产链路

## 资产边界

- 抽卡库是独立于视频任务的公共资产库，按画面风格隔离。
- 每项资产包含 `label`、`description`、审核状态和一张 3:4 角色设定图；设定图同时展示正面、四分之三侧面、纯侧面和全身。
- 只有人工审核为 `approved` 的资产可以参与任务匹配。任务创建时会把角色图冻结复制到任务目录，之后公共资产停用或删除不会破坏历史任务。
- 抽卡在独立后台线程执行；若后台重启中断，遗留的 `queued` 记录会在下次启动变为可见错误，不会自动重复付费请求，也不会永久显示为排队。
- `story_name` 是当前故事称呼（例如“我”），`asset.label` 是公共资产名称（例如“青年女”），真正关联依赖唯一 `asset_id`。同画风重名会自动保存为“名称 2”“名称 3”，避免人工审核混淆。

## 任务匹配

1. 文本模型从文案提取真正出镜的角色，建立稳定的 `role_id`、剧情称呼与外观描述。
2. AI 只在当前画风的已审核资产中匹配，性别、年龄段或核心外观不合适时返回空匹配。
3. 缺少资产时，界面保留红色角色卡；点击该卡片的“去抽卡”会直接带入通用资产名和人物要求并提交候选。
4. 分镜规划必须为每幕输出 `cast_ids`。图片阶段只选择当前图片内实际出镜角色，不会把整部文案的全部人物图都上传。

当前界面把第3步简化为每个缺失角色卡片上的“去抽卡”：单击即以年龄段和性别生成通用资产名并提交一张候选，无需复制人物描述；审核通过后按 `role_id` 直接回填，卡片由红色变为绿色。若库中已有完全相同描述的已审核资产，匹配接口也会直接用ID补齐。

## 图片请求结构

请求图片的顺序固定为：画风参考图（仅需要内置参考图的画风）→ 当前分镜角色设定图。提示词先写当前分镜，再声明每张输入图的单一职责、角色白名单和画风规则。即使中转接口只接收 1000 字提示词，压缩也优先保留当前剧情。

四个已配置图片节点的真实参考图上限分别为 16、16、15、10 张。能力记录在各节点的 `max_input_images` 中；调度器只选能容纳本次全部参考图的节点，未知节点保守按 4 张处理。

同一视频任务用哈希选择首选图片节点并保持亲和，以减少不同中转实现造成的风格漂移。首选节点发生 429、5xx、冷却或其他真实调用错误时才切换兼容节点。任务状态的 `image_generation_audit` 按图片记录最终节点、模型、参考图清单和生成时间，便于追查漂移。

## 主要持久化结构

公共资产：`.webapp/character-library/<style-hash>/<asset-id>/asset.json`

任务：`.webapp/jobs/<job-id>/job.json`
